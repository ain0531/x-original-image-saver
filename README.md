# X 原寸画像保存

Chrome 116以降、Manifest V3の拡張機能。ツールバーのアイコンでサイドパネルを開きます。
現行バージョン：**0.5.1**。サイドパネルとオプションにもバージョンを表示します。
詳しい動作は [現行仕様書](SPECIFICATION.md) を参照してください。

## ビルド・更新

```sh
npm ci
npm test
```

`chrome://extensions` の「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選びます。
更新時は拡張機能を再読み込みしてください。0.2.0では動画配信ホスト `video.twimg.com` のアクセス権限を追加しています。
投稿内ボタンやページ内の画像情報監視も更新する場合は、Xのページを再読み込みします。

## ブックマーク保存と初回の取得

「まとめて保存」の下に保存モードを選ぶプルダウンがあります。パネルを開いた時は「ブックマークから保存」です。
このモードは従来と同じで、閲覧中のページにかかわらず、バックグラウンドの通信で
ブックマーク一覧のデータを取得します。まずデータ通信だけで最初の応答まで確認します。
初回取得に失敗した場合に限り、同じウィンドウに非アクティブのブックマークタブを1つ開きます。
X自身が取得した先頭ページのJSONと取得設定を受け取り、通信後にタブを自動で閉じます。
そのデータから保存を開始するため、ボタンを押し直す必要はありません。
スクロールや元の閲覧ページの移動は行いません。

Xにユーザー自身がログインしている必要があります。X自身のGraphQL GET通信から
取得設定を学習します。学習済み取得先がない場合は、XのHTMLと公開クライアント資産を
テキストとして取得し、現在のBookmarks操作ID・機能設定・クライアント共通Bearerを解析します。
取得したJavaScriptは実行しません。開発者APIキーや固定操作IDは不要です。

認証設定は `storage.session` のメモリー内だけに保持します。ログインCookieは保存しません。
ログインセッションが変わった場合は停止します。未ログイン・HTTP 429ではタブを開きません。
初回タブの待機は最大30秒。成功・失敗・タイムアウトのいずれでも、拡張が開いたタブを閉じます。
ブラウザーの同じログインセッションで初回タブによる取得を済ませた後は、タブを繰り返し開かず、
取得できなければ理由を表示して停止します。ブラウザー再起動・拡張再読み込みでは設定を取り直します。
既に開いていたユーザーのタブは閉じません。別のページの画像は保存しません。
Xの内部仕様や認証条件が変わると取得できない場合があります。実際のXへの接続は未検証です。

パネルに「ブックマークのデータを取得（タブなし）」と表示します。
初期上限は20ページ・30秒。1要求は20件で、Xが返す件数は応答内容によります。
新規開始は一覧の先頭から、再開は保持したカーソルから取得します。
取得と最大4件のファイル転送を並行します。全メディア一覧を利用し、2枚目以降や複数動画も対象にします。
未確認投稿・失敗・上限停止は結果に表示します。

## 個別アカウントのメディア保存

対象アカウントのプロフィール・投稿詳細・返信一覧などを開き、モードを「個別アカウントからの保存」にして「まとめて保存」を押します。
アドレスのアカウントIDからメディア一覧を自動で取得し、画像と動画を保存します。
写真のみのメディアページを開いた場合は画像のみです。ホーム・検索・通知など、対象アカウントを特定できないページでは開始しません。

X自身の通信からUserMediaとアカウントID取得の設定を学習し、対象のアカウントを照合して
バックグラウンドで一覧を取得します。画面のスクロールや表示画像の収集は行いません。
設定が不明な場合はHTML・公開クライアント資産をテキストとして解析し、観測済みの機能設定も補います。取得設定不足の案内をログインエラーとは扱わず、初回に必要なら
非アクティブの取得用メディアタブを開きます。そのタブは通信後・失敗時・30秒の時間切れ時に閉じます。
初回はX自身が返した先頭メディア応答を使い、別のアカウントID照会が発生するまで待ちません。
GET・POSTの両方に対応し、確認したアカウントIDで続きもバックグラウンド取得します。
再実行時は同じログインセッションの確認済みIDを利用して、新しい先頭ページを取得します。
ブックマーク通信で取得済みの認証・機能設定も共用します。メディア通信を検出できない場合は、
Xページで読み込まれた公開スクリプトと有効な機能設定から取得先を確認し、直接取得を試みます。
失敗時には直接取得の具体的なエラーも表示します。
アカウント取得の返信ダウンボート設定が未取得の場合だけ、互換値 `false` を使用します。
Xから確認できた値があれば優先し、その他の未知の設定は一律に変更しません。
メディア応答にアカウントIDが省略されていても、照会済みの対象IDへ直接要求した一覧は取得できます。
応答に別のID・アカウント名が明示されている場合や、未知の応答形式では停止して理由を表示します。
一度初期化を済ませた同じセッション・対象では、後の取得失敗でタブを繰り返し開きません。

取得と最大4件の転送を並行し、オプションの取得上限・保存先・ファイル名と、原寸画像・最高MP4・
保存済みIDの重複防止を共用します。写真のみでは動画・GIFを除外し、引用先の添付メディアは収集しません。
新規開始は先頭から、上限停止後の「未処理分・続きから再開」は記録したカーソルからです。
再開は保存開始時のモードと対象アカウントを使い、プルダウンの現在値では変更しません。
ログインセッションが同じなら元の閲覧タブを閉じた後も再開できます。実際のX接続は未検証です。

## 原寸保存・画像IDによる重複防止

- `name=orig` の画像だけを保存します。縮小画像へのフォールバックは行いません。
- 保存完了は、Chromeの完了状態・ファイル存在・画像MIME・原寸URLで確認して記録します。
- 記録キーは `savedImage:<画像ID>`。保存済みIDは期限なく保持し、常にスキップします。
- Chromeの履歴削除、ファイル移動・削除、保存先変更、形式違いでも記録済みIDを再保存しません。
- 初回にChromeの過去の原寸完了履歴を照合してIDを取り込みます。旧拡張履歴も移行します。
- 保存済みの証拠がない・履歴が読めない場合はfail-safeで保存します。両方の履歴が失われた場合、過去の保存は判定できません。
- 「保存履歴を消去」は明示的に保存済みIDを消します。画像ファイルは削除しません。

## 動画・アニメーションGIFの保存

投稿データのMP4候補から最高ビットレートを選びます。同率なら解像度の大きい候補を優先します。
これはXの応答から取得可能なMP4であり、投稿者がアップロードした元ファイルの保証ではありません。
アニメーションGIFもMP4として保存します。サムネイルを動画の代わりに保存しません。

動画のメディアIDを `savedVideo:<動画ID>` で期限なく管理します。完了状態・ファイル存在・
MP4のMIME・選択した動画URLを確認してから記録し、保存済みIDはスキップします。
過去のChrome動画履歴だけでは最高ビットレートを確認できないため、自動取り込みはしません。
記録が不明なら保存します。「保存履歴を消去」は画像・動画の両方の記録を消します。

HLSのみの動画、動画IDや最高ビットレートを確認できない動画は、未確認として理由を表示します。
転送に失敗しても低画質に切り替えません。画像の転送監視は約2分、動画は約10分で時間切れになります。

「オプション」で取得上限、Chromeのダウンロード先からのサブフォルダ、ファイル名を設定します。
初期ファイル名は `{mediaId}_orig.{format}`。絶対パスは指定できません。
新規ジョブは現在の設定を、再開は開始時の設定を使います。
一括保存に開始確認ポップアップはありません。Chrome自身の保存先確認設定は適用されます。

## 現在の投稿・特別保存

「現在の投稿の画像・動画を保存」は、開いているXの投稿を対象にします。
ボタン下の「保存先を指定」は初期状態OFFで、オプションのフォルダ・ファイル名で自動保存します。
ONにすると、設定された名前・フォルダを候補として保存先を手動選択できます。
この設定は投稿内の「ローカル保存」と共通で、チェック状態を保存してパネルを開き直しても復元します。
ローカル保存の予約は受付時のチェック状態を保持し、ONなら各ファイルの保存時に保存先を選択します。
ページ内の画像と監視済みの全メディア一覧を利用します。動画は投稿データを確認できる場合に保存します。

監視キャッシュがない・不完全な場合は、対象記事の表示に使われているデータから全メディア一覧を補います。
対象投稿IDの全一覧を確認できた場合だけ利用し、隣の投稿や一部分の一覧で確認済みにはしません。
同じアカウントの投稿データはページ移動後も利用できます。アカウント変更時は使い回しません。
開いたままのページに監視コードがない場合は、保存時に拡張機能のコードを補います。
全一覧を確認できれば、タイムライン全体の読み込み表示を待ちません。

個別保存で保存先ダイアログや転送をユーザーがキャンセルしたファイルは、未処理・失敗に残しません。
「キャンセル」として処理を終了し、他の保存を妨げません。保存済みIDには登録しないため、改めて保存できます。
旧バージョンで失敗として残った明示的なキャンセル記録も、更新後の起動時に解除します。
通信失敗・時間切れ・ブラウザー終了はキャンセルとは区別し、再試行用に保持します。

拡張機能が有効な間、投稿の最下部の操作列に「特別保存」を追加します。
押すとXの操作ボタンから「いいね」と「ブックマーク」を付けます。既存の状態は維持し、
再クリックで解除しません。両方の反映を確認すると「特別保存済み」、失敗すると理由を表示します。
特別保存では画像をダウンロードしません。後から読み込まれた投稿にもボタンを追加します。

「特別保存」の下に「ローカル保存」を表示します。タイムラインのその投稿の画像・動画を、
投稿詳細ページを開かずに保存できます。「保存先を指定」がOFFならオプションのフォルダ・ファイル名を使って自動保存し、ONなら保存先を選択します。
原寸画像・最高ビットレートMP4・メディアIDによる重複防止は現在の投稿の保存と共通です。
保存指示を永続キューに予約し、前のローカル保存中でも別の投稿から指示できます。
予約時に投稿のメディア情報と保存先を記録し、転送は投稿順・ファイル順に1件ずつ進めます。
予約後に投稿が画面から消えたりタブを閉じたりしても保存を続け、再起動時も復旧します。
保存結果・失敗理由を投稿のボタン下に表示します。失敗・情報不足があっても次の予約を処理し、
再試行は対象投稿の「ローカル保存」を押します。保存済みファイルはスキップします。
サイドパネルにはローカル保存の予約・処理中件数と要確認件数を表示します。
サイドパネルの「現在の投稿の画像・動画を保存」も引き続き利用できます。

そのボタンの下に「同時にいいねする」を追加しています。初期状態OFFで、設定は永続保存し、
サイドパネルの個別保存と投稿内のローカル保存で共通に使います。ONなら指示時に対象投稿の
Xのいいねボタンを操作します。既にいいね済みなら何もしません。再保存でも解除しません。
ブックマークは変更しません。いいねの失敗は表示し、メディア保存は続けます。

## 一時停止・復旧・検証

一時停止は新たな取得・転送の開始を止めます。進行中の転送は完了する場合があります。
ジョブ・画像キュー・カーソルを永続化し、再開で失敗画像を再試行します。
新方式の再開は開始元のタブを閉じても使えます。同じログインセッションが必要です。
旧方式で作ったジョブの復旧は元のページを確認します。

`npm test` はビルド後、モックChrome API・DOM・通信で135件のテストを実行します。
タブなし取得、認証失敗、アカウント変更、カーソル再開、過去の原寸履歴の取り込み、
期限のない保存済みID、複数画像・動画、最高MP4の選択、動画ID重複防止、未対応動画の報告、原寸確認、失敗復旧、投稿ボタンを検証します。
モックテストは実際のXへの接続成功、速度、全ブックマークの網羅性を保証しません。

Chromeのバックグラウンド通信とメモリー内保存の仕様：
[ネットワーク要求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、
[Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage)。
